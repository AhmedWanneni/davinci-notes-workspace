# UX Review: Sync Conflicts Modal & Panel

## 1. Overview
The Sync Conflicts Panel (`SyncConflictsPanel.tsx`) identifies and helps resolve conflicting file versions generated by background sync services (such as Syncthing or cloud sync providers), such as `note.sync-conflict-20261015-120000.md`.
- **Entry points**: Status Bar sync warning indicator, Settings > Sync > "Resolve Conflicts", or notification prompt when duplicate sync conflict files are detected.
- **Current state**: Panel displaying conflict count, list of conflict files with timestamps, buttons to "Open Conflict", "Open Original", and "Delete".

## 3. Issues

### CONFLICT-01: Destructive file deletion without confirmation modal or trash safety
- **Severity**: Blocker
- **Rule violated**: H5 Error prevention / H3 User control and freedom / H9 Error recovery
- **Evidence**: `apps/desktop/src/components/SyncConflictsPanel/SyncConflictsPanel.tsx:12-18, 68-75` (`await deleteNoteInVault(conflictPath)`) `[Observed]`
- **Why it hurts the user**: If a user accidentally clicks "Delete" instead of "Open", their synced notes data is permanently deleted from the filesystem with no confirmation prompt and no undo!
- **Suggested fix**: Trigger a confirmation dialog (`"Permanently delete conflict file [name]? This action cannot be undone."`) before executing deletion, or move the file to the system Trash (`trash` API) rather than hard deleting.
- **Effort**: S

### CONFLICT-02: Missing side-by-side diff comparison
- **Severity**: High
- **Rule violated**: Jakob's Law / H6 Recognition over recall / H7 Flexibility
- **Evidence**: `apps/desktop/src/components/SyncConflictsPanel/SyncConflictsPanel.tsx:49-76` `[Code-Read Only]`
- **Why it hurts the user**: Users cannot see what changed between the original note and the conflicted copy without opening both notes in separate editor panes and comparing line by line.
- **Suggested fix**: Provide a "Review Diff" button that opens the existing CodeMirror diff viewer component (`GitDiffViewer` or similar split diff) to easily compare changes.
- **Effort**: M

### CONFLICT-03: Missing explanation of conflict cause and prevention
- **Severity**: Low
- **Rule violated**: H10 Help and documentation
- **Evidence**: `apps/desktop/src/components/SyncConflictsPanel/SyncConflictsPanel.tsx:32-37` `[Code-Read Only]`
- **Why it hurts the user**: Non-technical users are confused about what a `.sync-conflict` file is and why it appeared.
- **Suggested fix**: Add an info callout explaining: *"Conflicts occur when a note is edited simultaneously on two devices before syncing. Review differences and delete the version you don't need."*
- **Effort**: S

## 5. What Works Well
- Instant detection of Syncthing conflict filename patterns without heavy disk scans.
- Direct jump buttons to open conflicted notes in the active workspace.
- Clear empty state when no conflicts exist.

---

## 6. Quick Wins vs Larger Work
- **Quick Win**: Add confirmation alert dialog before deleting conflict files (≤30 min).
- **Quick Win**: Add informational conflict explanation banner (≤15 min).
- **Larger Work**: Embed a side-by-side visual diff resolver with "Keep Mine" / "Keep Theirs" / "Merge Both" buttons.
